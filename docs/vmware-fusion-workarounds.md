# VMware Fusion workarounds, lineage for the stargazer VM

Every place where stargazer's NixOS configuration, scripts or runbook bends to
VMware Fusion (26.0.1 on Apple silicon, vmwgfx graphics, NVMe disk), with the
evidence that forced it and what happens to it on another hypervisor. Kept so a
move off Fusion is a checklist, not an archaeology dig. The Parallels record it
replaces is `docs/parallels-workarounds.md`.

Legend for the last column: **drop** = delete on another hypervisor, **keep** =
hypervisor-agnostic, **re-test** = the mechanism is generic but the trigger was
Fusion-specific.

| # | Workaround | Where | Evidence (date) | Elsewhere |
|---|-----------|-------|-----------------|-----------|
| 1 | **Hyprland vmwgfx DMA-BUF patch**, vendored and pinned to 0.56.2. A version check turns a nixpkgs bump into an evaluation error instead of a silently unpatched session. | `modules/nixos/vmware-guest.nix`, `modules/nixos/patches/hyprland-0.56.2-vmwgfx-dmabuf.patch` | 2026-09-14: unpatched Hyprland rejects every GPU client buffer on vmwgfx (alacritty, GL apps), while shared-memory clients keep working. | **drop** when Hyprland discussion #12966 lands upstream. Re-check the patch on every Hyprland bump until then. |
| 2 | **Resize follower timing**: 0.5 s poll, 1 stable poll, 0 px hysteresis, instead of the Parallels-era 2 s / 3 / 16 px. | `modules/nixos/vmware-guest.nix` | 2026-09-14: Fusion reports each window size once and exactly. The old debounce cost about 8 s per resize, the new values about 1 s, with no drift after a mode change. | **re-test**. The defaults in `vm-guest.nix` suit a hypervisor that reports sizes noisily. |
| 3 | **Retina pixels**: `gui.fitGuestUsingNativeDisplayResolution` in the `.vmx` plus Hyprland scale 2 in the host config. | `scripts/stargazer-vm`, `hosts/stargazer/default.nix` | 2026-09-14: without the key the guest gets logical pixels and text is soft. The scale keeps text at its usual size. | **re-test**. Any hypervisor that can hand over the full panel resolution needs the same pair. |
| 4 | **Two display facts with no fix**: the boot console runs at 1280x800 until the tools start in the session, and a resize is only seen while the Fusion window is on screen. | `hosts/stargazer/README.md` §5 and §10 | 2026-09-15: both reproduced by hand. Fusion stops sending the window size when the window is hidden. | **keep as notes**. They are operator expectations, not configuration. |
| 5 | **`headless = false`** on the VMware guest module, and the copy/paste agent started from the Hyprland session through `extraExecOnce`. | `modules/nixos/vmware-guest.nix` | 2026-09-15: the module's `headless` default is `!services.xserver.enable`, always true under Hyprland, and headless drops `vmware-user`. The module otherwise starts that agent from an X display manager's session commands, which greetd never runs. | **drop**. Both are VMware guest module details. |
| 6 | **Clipboard bridge** between the X11 CLIPBOARD and the Wayland clipboard, as a user service. | `modules/nixos/vmware-guest.nix` | 2026-09-15: Hyprland's XWM.cpp refuses clipboard access to X11 clients without focus, and the agent has no window, so copies stopped at XWayland in both directions. Verified fixed with the probe in README §10. | **drop** if Hyprland relaxes the focus rule or open-vm-tools gains a Wayland path. The cost meanwhile: any X11 client on this host can read text copied in a Wayland app. |
| 7 | **HID passthrough keys** `usb.generic.allowHID` and `usb.generic.allowLastHID` in the `.vmx`. | `scripts/stargazer-vm` | 2026-09-15: without both, Fusion keeps the YubiKey on the Mac and the menu will not hand it over. With them, WebAuthn registration and authentication passed in the guest. | **drop**. Other hypervisors expose USB passthrough differently. |
| 8 | **`uuid.action = "keep"`** in the `.vmx`. | `scripts/stargazer-vm` | 2026-09-15: without it a power-on stops at the "moved or copied" question, which blocks `vmrun` until someone clicks, and the copy answer changes the hardware UUID and MAC. | **drop**. |
| 9 | **Secure Boot by appending our db certificate**: `uefi.secureBoot.dbDefault.file0` plus `dbDefault.append`, with the variable store regenerated on every enable, the first of which keeps the pre-Secure-Boot NVRAM file as the backup. PK and KEK stay VMware's. | `scripts/stargazer-vm secure-boot` | 2026-09-14: Fusion loads the default key set and `dbDefault.file0` only when it creates the NVRAM file. A negative test passed, with `SECUREBOOT: Image DENIED` in `vmware.log` for an unsigned image. | **re-test**. Plain lanzaboote and a firmware that accepts a custom db carry over. The `.vmx` keys do not. |
| 10 | **DNS does not come from the NAT lease**: 1.1.1.1 written into the installer's `resolv.conf` by hand, and `dhcpV4Config.UseDNS = false` on the installed guest. | `hosts/stargazer/README.md` §4.1, `modules/nixos/vmware-guest.nix` | 2026-09-14: Fusion's NAT DNS proxy does not resolve on behemoth. The lease points the guest at the gateway, which answers nothing, so the installer cannot reach GitHub. | **re-test**. The installed guest's own resolvers (`modules/nixos/base.nix`) are wanted everywhere. The installer line is Fusion-specific. |
| 11 | **SSH open on the NAT link `enp2s0`**, next to the tailnet. | `hosts/stargazer/default.nix` | 2026-09-14: VMware's guest operations need a guest password, which this host does not have, so SSH on the NAT address is how behemoth reaches a fresh install before it joins the tailnet. | **re-test**. The link name follows the vmxnet3 PCI slot and changes with the NIC. |
| 12 | **greetd must be restarted after a Hyprland package change**, with no session running. | `hosts/stargazer/README.md` §9 | 2026-09-14. | **keep**. Not a Fusion property. |
| 13 | **`vmcli MKS sendKeyEvent` needs vSphere's USB HID encoding** `(usage << 16) \| 7` and a HID modifier bitmask. Bare usage IDs are silently ignored. | `scripts/stargazer-vm` | 2026-09-14: found while making `type` and `key` work against the installer console. | **drop**. Every hypervisor has its own console input path. |
| 14 | **Fusion is not declarable**: no Homebrew cask, so the installer comes from Broadcom's portal with an account and a trade-compliance form. | `hosts/stargazer/README.md` §1 | 2026-09-14: the cask was disabled for that reason. | **drop**. This is the one cost that cannot be fixed in the repo. |
